## Independent native subset harness

`tests/upstream/146` adapts the completed #218 harness (commit `7fdb143`) after
inspection of #218 and #129 docs/tests. It compiles production NAction, Qxt
common code, NPlaylistWidget/item, settings, playlist data/storage, utilities,
track formatter, GStreamer playback engine and TagLib reader **from this
worktree**. It has no dependency on the #218 branch being merged and does not
compile full NPlayer. The small Previous/Next connections match actionManager,
with window-level QAction attachment matching NPlayer.

Plugin discovery returns the real engine. Existing `_TESTS_` synchronized
fakesinks replace only physical audio/video outputs; decoding, stream events,
Qt focus/shortcut/model behavior and TagLib file I/O remain real. Native Qxt
registration/filter methods are copied from #218 as **fatal-if-called** seams,
not mocks reporting registration success. No production files are modified.

FFmpeg/libmp3lame generates one finite 30-second MP3, copied into **20 distinct
files** and tagged via TagLib ID3v2.4 with unique artist/title/album strings,
including Portuguese Unicode. All fixtures are temporary and generated locally;
no user media or upstream attachments are redistributed. The display format is
explicitly `%a - %t - %A`, avoiding filename fallback as a false tag success.

## Assertions and results

Four data cases combine custom Up/Down versus default Z/B and ScrollToItem
on/off. Each traverses every file forward and back. The suite also checks that
unbound Up/Down retain ordinary playlist selection without changing playback.

- Twenty distinct playlist IDs, exact current file, playing row/pointer/ID,
  exact artist/title/album display text, positive duration, title format, playing
  flag and absence of failed flag are checked.
- Each traversal has exactly one action and mediaChanged per key, and the
  engine's emitted media context ID matches the intended row. Previous playing
  flags are cleared. No second activation or playback restart is needed.
- The final row begins outside the viewport with duration `-1`; its metadata is
  populated when played. In no-scroll cases it remains outside the viewport.
- Assertions run **inside playingItemChanged**, before queued repaint or
  visible-item metadata work can mask an empty/stale title. The harness waits
  for asynchronous GStreamer STREAM_START/row transition, not for metadata to
  eventually become correct after notification.
- Reverse traversal seeds a nonempty stale cached title with the existing
  format/duration and requires real on-disk metadata to replace it on activation.
- Default Z/B settings remain unchanged; unbound arrows only change selection.
  Preferences editing/persistence/conflict UI is not emulated by these tests.
