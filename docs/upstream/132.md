## Defect and fix

The writer stores `PlaylistRow` as exactly two strings: row index and normalized playback position. The loader previously checked only that the list was nonempty before `at(1)`, which aborts on a one-value record in an assertion-enabled build. Unchecked numeric conversion also selected track zero for non-numeric/overflowing rows and attempted restoration for invalid positions.

The loader now accepts only a two-value record, checks both conversions, checks that position is finite and within `[0, 1]`, and validates the row against the loaded playlist. A damaged record leaves the successfully loaded playlist intact without selecting media or starting playback. Existing valid-session behavior is unchanged:

| RestorePlaylist | StartPaused | Existing behavior verified |
| --- | --- | --- |
| false | false | Do not load playlist or media; remain stopped |
| false | true | Do not load playlist or media; remain stopped |
| true | false | Load playlist, select saved row, play at saved position |
| true | true | Load playlist and stage saved row/position without starting playback; explicit Play continues there |

For the GStreamer engine, the existing `StartPaused` path is **stopped with staged media**, not an active PAUSED pipeline. The test preserves that distinction; this patch does not change it.

## Reproduction

Prerequisites used: Linux, GCC 14.2, CMake 3.31.6, Qt 6.8.2 (Widgets/Test/Qml/Svg/SvgWidgets/Network/UiTools/Core5Compat), GStreamer development/runtime 1.26.2, TagLib 2.0.2, zlib, pkg-config; Xvfb for the additional xcb run.

From this worktree:

```sh
BUILD=/home/hermes/workspace/nulloy-swarm/evidence/132/build
LOCK=/home/hermes/workspace/nulloy-swarm/build.lock
cmake -S tests/upstream/132 -B "$BUILD" \
  -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_FLAGS_DEBUG=-g0
flock -w 600 "$LOCK" sh -c "cmake --build '$BUILD' -j1 && ctest --test-dir '$BUILD' --output-on-failure -V"
flock -w 600 "$LOCK" sh -c "ctest --test-dir '$BUILD' --repeat until-fail:3 --output-on-failure -V"
flock -w 600 "$LOCK" sh -c "QT_QPA_PLATFORM=xcb xvfb-run -a '$BUILD/test132'"
```

`-g0` omits debug symbols, not assertions. Single-case invocations can pass `singleValueIsIgnored` or `invalidNumbersAreIgnored` to `test132` with `QT_QPA_PLATFORM=offscreen`.

## Limits and build notes

- The CMake harness and test-only platform shims were copied after inspection from #211's in-progress native harness, then adapted and committed locally. All sources used by this build are in **this** worktree; there is no execution dependency on changing/uncommitted #211 files.
- Linux-only harness shims disable global desktop hotkeys and provide a no-op Windows stock-font query required by the existing Qt6 appearance header. Player/restoration/playlist/settings/playback implementations are not stubbed. Native resources are used; custom skins, Windows appearance, global hotkeys, IPC, and packaging are not validated here.
- Production changes use Qt5/Qt6-common APIs; **Qt5 was not built or run** because its development packages are absent. The harness itself targets Qt6. Windows/macOS and other playback backends are untested.
- This does not test persistence of a new last-playing/paused flag, per-file resume, seeking at EOS during autoplay, recovery from malformed M3U contents, or physical audio output. Those are outside this finite stabilization scope.
- Initial builds were OOM-killed despite `-j1`: `/proc/meminfo` advertised roughly 3.7 GiB but the shared cgroup limit is **2 GiB**. Build retries are retained in evidence. The successful build and all later builds/tests use the shared `flock` lock. Do not run concurrent swarm builds based on host free-memory values.
- Baseline compiler/UI warnings include deprecated Qxt key combination syntax and duplicate UI object names. Offscreen runs emit the platform's `propagateSizeHints` warning; the Xvfb run is warning-free. No claim is made that the whole application or all unrelated suites were rebuilt/tested.
- Live upstream JSON, build logs, red logs, and green logs are retained in the evidence directory, not committed as generated artifacts. Parent review/publication remains separate; this branch makes no remote writes or PR changes.
