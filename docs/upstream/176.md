# Upstream #176 — recorder codecs and missing-plugin diagnostics

Issue: https://github.com/nulloy/nulloy/issues/176
Base: `027d81a583b07457a4fa5f18b3e7dcca50b05b58`.

Read the body and all seven comments and inspected the linked screenshots.
They show WAV filenames and a generic missing-plugin error on Windows/macOS,
not the audio codec or a downloadable reproducer. Another comment mentions
`.ifg`; that spelling is preserved, not assumed to mean a different extension.
The maintainer requested a sample after an earlier attempted release fix.
PR searches `#176`, `missing plugin`, `codec` found no matching work. Existing
fork resource port PR #6 is not a decoder installation fix.

## Result: no justified production change

The real current GStreamer engine plays generated PCM 16-bit, PCM 24-bit,
floating-point PCM, A-law and mu-law WAV fixtures to EOS without failure.
Microsoft/DVI ADPCM WAVs fail on this Linux installation because their decoders
are absent (`adpcmdec`, `avdec_adpcm_ms`, `avdec_adpcm_ima_wav` not found by
`gst-inspect-1.0`). These errors already identify the missing decoder and caps:

- `Microsoft ADPCM decoder`, `audio/x-adpcm, layout=(string)microsoft`
- `DVI ADPCM decoder`, `audio/x-adpcm, layout=(string)dvi`

This is a demonstrated dependency gap in the test environment, not proof of the
reporter's codec or a Windows package omission. The package script copies the
installed `lib/gstreamer-1.0` directory and its dependencies; without testing an
actual package and the original sample, changing decoder packaging is speculative.
No playback engine, top-level CMake, UI or installation code is changed here.

## Reproducible characterization

```sh
cmake -S tests/upstream/176 -B build-issue176 -G Ninja
cmake --build build-issue176 -j1
ctest --test-dir build-issue176 --output-on-failure
```

Requirements: Qt Core/Gui/Test, GStreamer development/base/good plugins,
ffmpeg. Uses real `playbackEngineGstreamer.cpp` and the existing `_TESTS_`
synchronized fake sinks (not an audible-output test). The only dependency shim
supplies process arguments; no playback or error handling is copied or mocked.

Seven recorder rows require baseline decoder playback, or for the two optional
ADPCM formats, actual EOS **or specifically actionable ADPCM missing-plugin
failure**, never arbitrary failure. A separate test temporarily sets every
A-law-capable decoder's registry rank to NONE in-process, verifies decoder caps
and a failed signal, restores ranks with RAII, and plays PCM successfully on the
same engine. Installed files and persistent registry contents are not modified.

Local baseline: ten Qt Test cases including setup/cleanup pass, Qt 6.8.2 and
GStreamer 1.26.2. This does not mean ADPCM decoded: two rows explicitly
characterize its absence. No skip conceals this result.

Next test: obtain the WAV/`.ifg` originals, identify their streams with ffprobe,
then execute these fixtures and those originals against an extracted Windows
package with private GStreamer paths and a fresh registry. If a codec is actually
missing from that package, fix the corresponding packaging dependency separately.
macOS and Windows Server 2012 R2 remain unvalidated platform reports.
