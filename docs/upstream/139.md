## Two reproduced, narrowly fixed defects

1. **A missing input retained the preceding complete waveform.** The original
   `start()` returned on a missing file before `reset()`. A native test first
   completed a generated WAV, started a nonexistent path, and failed because
   `peaks().isCompleted()` remained true. Reset now occurs immediately after stopping
   the previous job, before cache lookup and file existence checks. Successful warm
   cache lookup still replaces the reset peaks synchronously.
2. **Decode errors left the worker and pipeline alive.** A real file containing
   invalid audio caused GStreamer to report a stream-type error, but `isRunning()`
   remained true beyond the test's wait. The error branch only logged the error;
   unlike EOS, it did not call `stop()`. It now releases the pipeline, stops the
   polling timer, and joins the worker. The test verifies no completed cache is
   written and that a subsequent valid recording completes.

Both tests failed before their respective fixes (`red-missing.txt`, `red-error.txt`)
and then passed (`green-regressions.txt`). Neither proves the cause of #139's UI freeze.
Only `src/plugins/pluginGstreamer/waveformBuilderGstreamer.cpp` changes production
behavior. The abstract cache and peak algorithm are unmodified.

## Standalone native harness

```sh
cmake -S tests/upstream/139 -B /absolute/outside/build139 -G Ninja \
  -DCMAKE_BUILD_TYPE=Release
cmake --build /absolute/outside/build139 -j1
QT_QPA_PLATFORM=offscreen ctest --test-dir /absolute/outside/build139 \
  --no-tests=error --timeout 180 --output-on-failure
python3 tests/upstream/139/summarize.py /absolute/outside/build139/waveform-metrics.jsonl
```

Dependencies: C++17, CMake, Qt Core/Gui/Test, GStreamer development files and
base/good runtime plugins, and ffmpeg with FLAC/libvorbis encoders. Qt major can be
selected with `-DNULLOY_QT_MAJOR=5`; only Qt 6.8.2 was available for this run.
Qt5/6 production code paths remain compatible; a Qt5 build is not claimed.

Fixtures are generated automatically by the test. No downloaded/private media,
pre-generated fixtures, copied algorithm, stubbed builder, or audio output device is
required. The executable compiles the production GStreamer builder, abstract builder,
peak implementation, and `common.cpp`. Its portable cache is isolated under the
out-of-tree executable's `Data` directory; it does not use a user's Nulloy cache.
Do not run two copies from the same build directory concurrently.

Coverage:

- Generated 2-second stereo WAV/Ogg and 600-second stereo WAV/FLAC, 44.1 kHz PCM.
  The square-wave fixture has a quieter head and louder final quarter. Completion
  requires EOS, a stopped worker, bounded peak count, head/tail amplitude checks,
  and final position/index. The last two bins are checked together because the
  final bin may be shorter than a full signal period.
- One cold waveform-cache run and two warm **fresh-builder disk-cache** runs per
  format; all serialized peak values must match by SHA-256, and a warm hit must
  complete inside `start()` without starting a worker.
- Actual cache serialization/compression at 1–100 entries, plus loads at 1/10/100.
  A test subclass exposes only the existing protected cache-store call. Stored peaks
  originate from a real decode, and media entries are hard links to the same real
  recording. No artificial peak records are constructed. Unsupported hard-link
  filesystems explicitly skip this characterization.
- 50 cancellations and 50 destructors during a long recording at 0/1/10 ms delays;
  no partial cache write, stopped reusable worker, and successful later decoding.
- Rename an accented-name music directory and unlink an input while its builder
  is running, then complete the waveform and retry the old/missing path. Local
  Linux open-file semantics permit both. Filesystems prohibiting the operation
  explicitly skip it rather than pretending to reproduce it.
- The two test-first missing-input/error regressions above.

The JSONL file defaults to `build139/waveform-metrics.jsonl`; set `WAVEFORM_METRICS`
to override it. `summarize.py` rejects incomplete full runs and verifies all 218
measurement rows, including 50 cancellation and 50 close samples. Passing metrics
alone are not a test verdict; retain CTest/QtTest output as well.

## Measured evidence

Evidence root for this investigation:
`/home/hermes/workspace/nulloy-swarm/evidence/waveform/`.

The accepted bounded run is `ctest-600-locked.txt`, `metrics-600-locked.jsonl`, and
`summary-600-locked.json`: **12 QtTest passes, zero failures/skips; one CTest passed
in 5.92 seconds**, including fixture creation. Release build, GCC 14.2, Debian 13,
Qt 6.8.2, GStreamer 1.26.2, local Linux filesystem. Actual cgroup limits were one
CPU and 2 GiB, despite host `free` displaying more memory.

A shared `flock /home/hermes/workspace/nulloy-swarm/build.lock` serialized the
accepted build/test with the other workstreams. Earlier concurrent builds suffered
OOM kills and heavily contended measurements; their files are retained for diagnosis,
**not used as representative performance data**. These single-run measurements are
characterization, not portable performance guarantees.

| Fixture | Cold completion ms | Warm disk completion ms (two runs) | Peak pairs |
|---|---:|---:|---:|
| 2 s WAV | 108.827 | 0.226 / 0.133 | 87 |
| 2 s Ogg | 98.834 | 0.237 / 0.183 | 87 |
| 600 s WAV | 298.235 | 0.488 / 0.385 | 1,616 |
| 600 s FLAC | 695.985 | 0.262 / 0.252 | 1,616 |

- Cancellation: median 0.396 ms, maximum 5.089 ms across 50 attempts.
- Destructor: median 0.388 ms, maximum 2.387 ms across 50 attempts.
- Directory rename: 0.113 ms; waveform completed 303.920 ms after rename.
  After unlink, waveform completed in 253.982 ms. No local builder hang was observed.
- Cache store at 1/10/100 entries: 0.753 / 4.006 / 13.586 ms.
  Fresh-builder load: 0.485 / 3.183 / 10.674 ms. At 100 entries the file was 10,905 bytes.
- Maximum recorded process high-water RSS: 29,252 KiB. This includes the harness
  and GStreamer; it excludes child ffmpeg and filesystem page-cache accounting.
- Maximum 5 ms main-thread heartbeat gap during cold completion was 34.849 ms
  (FLAC); this measures event-loop scheduling, **not rendered window responsiveness**.

“Cold” means no waveform cache, not flushed OS caches. Completion time includes the
production 100 ms bus poll, EOS handling, synchronous cache save, and thread teardown;
fixture creation and builder `init()` are outside each completion timing. Cache store
measurements isolate the actual synchronous serialization/compression/file write but
are not fsync/durable-storage timings. Repeated square-wave peaks compress unusually
well; heterogeneous music, slow/network storage, and more realistic cache contents
must be profiled before setting #187 queue/prioritization limits.

An additional 3,600-second cold/warm-only run completed (six QtTest passes), but was
resource-contended and is not used for the table. A full 3,600-second run timed out
at 180 seconds under contention; that is an unresolved measurement limit, not proof
of a production deadlock. The first attempt also exceeded this container's 512 MiB
`/tmp`. For optional longer runs set `WAVEFORM_LONG_SECONDS=3600` and `TMPDIR` to a
sufficiently large disk-backed directory; the default CI run needs neither override.
