# Upstream #11 — file-handle release characterization

Issue: https://github.com/nulloy/nulloy/issues/11
Base: `027d81a583b07457a4fa5f18b3e7dcca50b05b58`.

Read the issue and its one comment, plus the linked [original report in
#8](https://github.com/nulloy/nulloy/issues/8#issuecomment-37907315). The requested
behavior is access from other applications while Nulloy plays the file. The
maintainer suggested GStreamer playback from RAM as a possible solution, not an
accepted implementation requirement. Loading entire tracks into RAM would be a
new memory/streaming policy and is not introduced speculatively.

PR sweep: `#11`, `file lock`, `file sharing`. Upstream PR #263 was found and read,
including its discussion. Its cover-reader clear-source release is already ported
to this baseline by fork PR #6. Do not duplicate that fix.

## What was actually tested

The standalone harness compiles real tag and cover readers. It creates one legal
MP3 sine fixture with ffmpeg, initializes both plugins before loading media,
and performs 100 open/read/clear cycles through each reader. On Linux it first
proves `/proc/self/fd` sees the live fixture descriptor, then asserts there are
zero matching descriptors after clearing either reader. Both readers invalidate
their shared source. Rename, TagLib title write, release, reopen/read and deletion
of an owned fixture also succeed.

```sh
cmake -S tests/upstream/11 -B build-issue11 -G Ninja
cmake --build build-issue11 -j1
ctest --test-dir build-issue11 --output-on-failure
```

Requires Qt Core/Gui/Test (Core5Compat on Qt 6), TagLib and ffmpeg. On the shared
worker environment wrap builds/tests in `flock /home/hermes/workspace/nulloy-swarm/build.lock`.
Local Linux Qt 6.8.2 / TagLib 2.0.2: five Qt Test cases pass (including setup and
cleanup), zero fail, one Windows-only sharing probe is explicitly skipped.

**No production change, no claim that Windows playback sharing is fixed.**
Linux's ability to rename an open file does not prove Windows compatibility; the
actual Linux descriptor checks establish only TagLib lifecycle behavior. The
GStreamer playback/waveform handles are not covered by this metadata harness.

## Windows evidence and next native test

The [TagLib 2.0.2 FileStream implementation](https://github.com/taglib/taglib/blob/v2.0.2/taglib/toolkit/tfilestream.cpp)
uses `CreateFileW(..., FILE_SHARE_READ, ...)`. [Microsoft's CreateFileW
contract](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)
defines incompatible requested access/share modes as `ERROR_SHARING_VIOLATION`;
read sharing does not grant write or delete sharing. This is a concrete dependency
lead, **not a runtime measurement of the fork's Windows DLL**.

The harness includes an actual Windows-native probe rather than pretending a
POSIX test measures sharing. While TagLib holds the fixture it logs the results of
read, write and delete-access `CreateFileW` calls, accepting only success or an
explicit sharing violation as characterized outcomes. After clearing the reader
it requires an exclusive read/write/delete-access handle to succeed. The guarded
Windows code has not been executed here.

Next test on a Windows runner with the release's exact DLLs:

1. Build/run this harness natively for both Qt variants; retain the Win32 results.
2. Add an independent helper process opening the same owned fixture via
   `CreateFileW` for read, write and delete access while the real player is in
   Play/Pause/Stop, with waveform work active and finished.
3. Record access flags, `GetLastError`, timing, and exact release/dependency versions;
   use Process Monitor or Sysinternals Handle to identify each holding component.
4. Only after isolating TagLib versus GStreamer ownership, write a failing native
   regression and choose a bounded lifetime/sharing fix. Check that external edits
   cannot race TagLib saves or invalidate active decoder buffers.

Wine or a Linux rename/flock probe cannot substitute for these native semantics.
No user files, GStreamer engine, UI, top-level CMake, or shared package tests changed.
