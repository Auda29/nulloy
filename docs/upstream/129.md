# Upstream #129: preserve pause when removing playlist entries

## Scope and behavior

[Issue #129](https://github.com/nulloy/nulloy/issues/129) reports three symptoms in
Nulloy 0.8.2 Alpha on macOS Sierra: a freeze deleting roughly 5,000 entries,
unexpected playback while paused, and Backspace not removing entries. The live
issue has no comments. Issue-number and two symptom-keyword PR searches in both
upstream and this fork returned no matching work. History (`8c14916`, `9ff2c16`)
shows the existing activation condition includes paused playback; it is not a
newly documented requirement to resume on removal.

Only the demonstrated pause bug is changed: `removeSelected()` advances to a
replacement **only while playing**, rather than in every non-stopped state.
When paused and the loaded entry is removed, the engine retains that media and
position, remains paused, and the removed widget/ID is discarded. Keyboard focus
still moves to the existing replacement row. An explicit engine Play can resume
the retained media; activating a remaining row selects that row instead. This
matches the existing stopped-removal policy and avoids a transient play/pause
cycle or backend changes. Removing every selected entry still clears media and
stops. Playing removal keeps the previous end-of-list/LoopPlaylist policy.

`removeFiles()` is characterized, not redesigned: it removes matching paths,
including duplicates, and refreshes successor data without starting new media.
Its pre-existing omission of track-index/duration recomputation is **not fixed**
here and is excluded from those specific assertions. No UI, shortcut, skin,
backend, or top-level CMake changes are included.

## Real runtime harness and TDD

`tests/upstream/129` is an independent CMake project compiling the actual
playlist widget/item, settings, playlist data/storage, utilities, track formatter,
GStreamer playback engine, and TagLib reader. The only discovery seam is
`NPluginLoader::getPlugin()`, which supplies the real engine directly instead of
loading unrelated waveform/container plugins. The existing `_TESTS_` backend
switch replaces physical audio/video outputs with synchronized fakesinks;
decoding, media transitions, state signals, timers, Qt model/view, and TagLib I/O
remain real. Temporary PCM WAV files are generated locally.

TDD evidence under `/home/hermes/workspace/nulloy-swarm/evidence/129`:

- `red.txt`: original implementation fails `pausedCurrentRemoval`: actual
  PlaybackPlaying, expected PlaybackPaused.
- `green-initial.txt`: minimal condition change passes.
- `sabotage.txt`: restoring the original condition makes the test fail again.
- `runtime-final.txt` and `ctest-final.txt`: final split suite passes **10/10
  CTest tests** (functional suite plus nine benchmark cases), 13.49 seconds.
- `benchmark.json`: all **27** raw timing samples and computed summaries.

Functional checks cover current/next removal in Play/Pause/Stop, all-selected,
empty/no-selection, final-row LoopPlaylist on/off, duplicate paths with distinct
IDs, discontiguous selection, stale EOS/failure IDs, and actual successor handoff
after both selected-row and path removal. No stateChanged signal may unexpectedly
report Playing after paused/stopped removal. Position/media preservation and
selection-removal indices are checked. The large cases additionally verify exact
surviving IDs/paths/order, known-duration sums for selected removal, queued
GUI-event delivery, and widget destruction.

## Measured large-playlist checks

Environment: Debian 13, Qt 6.8.2, GStreamer 1.26.2, TagLib 2.0.2, GCC 14.2;
Linux offscreen Qt platform. The shared runner has a 2 GiB / 1 CPU cgroup limit.
Final measurements ran under the swarm build lock. GCC `-O0 -DNDEBUG
-ftrack-macro-expansion=0` was used after concurrent optimized compilations were
OOM-killed; these are **not release-optimized Windows measurements**.

Each size uses unique valid one-second WAV files; fixture generation is outside
the measured interval. Three fresh playlist loads are measured per case.
Select All uses the real `selectAll()` operation; alternating rows use a batched
Qt selection. “By path” removes alternating paths. Benchmarks run **stopped**;
the playback-state matrix is separate and uses four rows. Filesystem/OS caches
are not claimed cold. Load and selection timings are retained in raw evidence.

| Rows | Remove all: median ms | Alternating: median ms | By path: median ms |
| ---: | ---: | ---: | ---: |
| 100 | 0.315 | 2.033 | 0.149 |
| 1,000 | 4.801 | 26.552 | 4.993 |
| 5,000 | 14.880 | 507.751 | 111.699 |

Maximum measured removal-to-queued-event return at 5,000 rows was 36.201 ms
(all), 531.961 ms (alternating), and 123.427 ms (by path). This exposes a
nontrivial synchronous cost for discontiguous selection, not a reproduced
permanent hang. No speculative algorithm change is made. The audit's proposed
500 ms/2 s budgets are not historical upstream acceptance requirements and are
not asserted here; each CTest process has a 120-second hang timeout.

An exploratory harness initially selected every row individually, creating
thousands of separate selection ranges. Under concurrent resource pressure its
10-second exploratory guard failed. Replacing that setup with actual Select All
changed the tested operation substantially; that early output is retained as
`green-matrix.txt`, not presented as evidence of a production fix. A seek-based
fixture also sampled transient GStreamer Paused state; final removal tests wait
for ordinary playback position rather than injecting an unrelated flushing seek.

## Reproduce

From the repository root (a build directory outside `bin` keeps settings isolated):

```sh
cmake -S tests/upstream/129 -B /tmp/nulloy-129 -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_FLAGS_RELEASE='-O0 -DNDEBUG -ftrack-macro-expansion=0'
cmake --build /tmp/nulloy-129 -j1
ctest --test-dir /tmp/nulloy-129 -j1 --output-on-failure
QT_QPA_PLATFORM=offscreen /tmp/nulloy-129/testRemoval129 pausedCurrentRemoval
```

For the shared swarm, wrap build/test in
`flock /home/hermes/workspace/nulloy-swarm/build.lock sh -c '...'`.
The harness accepts `-DNULLOY_QT_MAJOR=5`; that configuration has **not** been
executed here. The production condition change uses APIs/enums already common to
Qt 5 and Qt 6. Existing compiler warnings (`QDropEvent::pos`, TagLib `length`,
TagLib `tagToKey` missing return) were not introduced or suppressed.

claim that every symptom of the original macOS issue is resolved**.
