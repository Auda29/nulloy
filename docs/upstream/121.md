# Upstream #121: shuffle characterization

[Issue #121](https://github.com/nulloy/nulloy/issues/121) has an empty body and no
comments. The live issue-number, “playlist randomization”, and “shuffle playlist”
PR searches returned no matching work. The fork already implements in-place
shuffle (`33388d1` includes prior item-lifetime work); no new shuffle semantics
or speculative production change are justified by this issue.

## Runtime result

The independent `tests/upstream/121` CMake harness compiles production
NPlaylistWidget/item, settings, playlist data/storage, track formatter,
GStreamer playback engine and TagLib. Plugin discovery is replaced solely to
provide the real engine directly; the existing `_TESTS_` synchronized fakesinks
replace physical output, not decoding/state/handoff. Temporary valid PCM WAVs
are generated; playlists deliberately repeat four paths with distinct IDs.

**12/12 CTest cases passed in 7.11 seconds** on Debian 13 / Qt 6.8.2 /
GStreamer 1.26.2 / TagLib 2.0.2 / GCC 14.2 (`-O0`). Evidence:
`/home/hermes/workspace/nulloy-swarm/evidence/121/ctest.txt` and the build's
`Testing/Temporary/LastTest.log`.

Every combination of 0/1/100/5000 entries and Play/Pause/Stop performs 20
shuffles, checking:

- Exact ID-to-path multiset, no loss/duplicate IDs, count and track indices.
- Playing item identity, loaded file and playback state remain unchanged;
  paused/stopped position is unchanged. Playing position naturally advances.
- No mediaChanged signal merely because of shuffling.
- With nonempty lists, actual playback handoff follows the final shuffled
  successor (including single-entry looping and duplicate file paths).
- Real M3U write and widget reload retain the shuffled path order and indices.
- Empty-list shuffle is exercised with externally loaded media in each state;
  it never dereferences a nonexistent item.

A random unchanged order is allowed. There is no flaky “must differ” assertion.
These are characterization tests of existing behavior: they passed on base
`027d81a`, and **no production fix or regression-red claim is made**.

## Reproduce

```sh
cmake -S tests/upstream/121 -B /tmp/nulloy-121 -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_FLAGS_RELEASE='-O0 -DNDEBUG -ftrack-macro-expansion=0'
cmake --build /tmp/nulloy-121 -j1
ctest --test-dir /tmp/nulloy-121 -j1 --output-on-failure
```

On the shared swarm wrap configure/build/test in
`flock /home/hermes/workspace/nulloy-swarm/build.lock sh -c '...'`.
The project accepts `NULLOY_QT_MAJOR=5`, but Qt 5 was not executed.

release package. The canonical Windows package/skins/plugin suites and real

Branch `fix/upstream-121` is independent of the #129 fix; parent review and
publication are pending. No upstream write/push/PR was made.
